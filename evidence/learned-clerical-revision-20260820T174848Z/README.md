# Learned clerical revision exploration

## Main result

The two-model substrate revised four stored control records after the
environment reversed each relation. The clerk wrote all four new records
correctly. The runtime kept the old versions, selected the newer versions for
matching devices, and the participant then made all 24 post-change matching
actions correctly. The frozen verdict is `revision_candidate`.

The run also found a governance defect. When gauge movement was hidden, the
clerk still invented complete-looking effect records. The exposed result was
necessary for reliable revision, but the runtime does not yet reject a record
whose source lacks the facts needed to support it.

This is an exploratory result about a harness instrument. Formation remains
null.

## The task

Each of two lineages contained two visible device designs. For example, an old
record could say that the first displayed control raises position and the
second lowers it. That record first guided a cold participant on new controls
with the same visible design.

The environment then reversed the relation. The participant acted from the old
record, so its action produced a movement that contradicted that record. A
separate 4B clerk saw which displayed actuator had been used, whether the gauge
rose or fell, and the visible design. It turned that sensory account into a
new two-control record.

The old and new records remained separate versioned objects. Each version
linked to the environment occurrence that caused it. For a later matching
device, a 4B normalizer wrote two visible feature fields. The runtime compared
those fields exactly and delivered the newest complete matching record to a
fresh 14B participant call.

The clerk never saw a later device's controls, position, target, expected
action, or score.

## What changed and what stayed fixed

All four old records were tested before the reversal. The participant made 24
of 24 pre-change actions correctly. It then made one counterexperience action
per record. All four actions followed the old policy, and all four environment
results contradicted the old record.

After revision, each lineage received two target directions for both known
designs, plus one novel design and one recombination of known features. Each
case was repeated three times under nine information conditions. The
participant model, action interface, and environment rules stayed fixed.

## What happened

The clerk and deterministic record path were exact on the evidence that was
actually exposed:

| Component | Exact |
| --- | ---: |
| Old versioned records | 4/4 |
| Exposed revised records | 4/4 |
| Later device normalizations | 12/12 |
| Structural selections, including empty unrelated selections | 12/12 |
| False selections on novel or recombined devices | 0/4 |

The post-change action scores were:

| Information delivered | Correct matching actions |
| --- | ---: |
| No retained information | 12/24 |
| Raw counterexperience | 12/24 |
| Newest exposed revision | 24/24 |
| Stale old record | 0/24 |
| Consequence-hidden revision | 6/24 |
| Exposed revision removed, leaving the old version | 0/24 |
| Old and new versions together | 7/24 |
| Supplied correct revision selected by normalized scope | 24/24 |
| Exposed revision selected by the environment-owned match | 24/24 |

The newest exposed revision made all 12 actions in each design and all 12 in
each target direction. Every three-call participant cell contained at least
two valid action objects.

Every condition made 6 of 12 unrelated actions. The revised branch therefore
preserved the cold score, though the cold score itself was only one half. The
normalizer and exact matcher delivered no record to the novel or recombined
devices.

## The hidden-consequence defect

The hidden clerk was told that gauge movement was unavailable. It nevertheless
wrote a selected actuator and movement for all four cases. The later prose and
parser stages turned all four claims into complete records. Three restated the
old relation. One happened to state the new relation correctly.

Because the runtime currently checks completeness but not whether the source
occurrence contains the facts claimed by the record, those unsupported records
could become the newest version. That branch made 6 of 24 matching actions.
Its large gap from the exposed branch supports attribution to the real
consequence, but the acceptance behavior is unsafe. A missing measurement must
block or quarantine a revision before chronology can make it current.

## What this supports

Within this small domain, a restricted clerk can turn counterevidence into a
new version that changes later action in the correct direction. The result did
not come from raw history, deletion, or merely showing both versions. Keeping
the stale record produced the old, now wrong policy. Selecting the exposed new
record matched known-correct supplied guidance.

This adds a bounded revision candidate to the learned clerical substrate. It
also shows why explicit version order matters: delivering both conflicting
versions without selecting the current one made only 7 of 24 matching actions.

## What this does not support

The experiment covers one immediate reversal in a tiny two-feature control
world. It does not show safe revision over long histories, conflicts between
several experiences, recovery from a mistaken update, or useful behavior in a
richer practice.

The runtime still accepts unsupported clerk claims when a required measurement
is absent. That defect should be fixed and tested before the mechanism is
treated as a safe revision substrate.

Known-correct supplied revisions also made all 24 matching actions. The result
does not show superiority over static guidance, autonomous model development,
or net practical value. Formation remains null.
