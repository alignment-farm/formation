# Post-executable-prediction boundary

Status: **independently review-stable post-contact problem definition, consumed
by the reviewed unselected-lineage route selection; retained as the problem
authority and licenses no additional route, mechanism, or model call**.

## Main point

The executable-prediction contact found one event worth explaining, but not a
developmental effect.

In World K, the first successor changed a wrong primary prediction into the
correct one. Its byte-identical repeat returned the exact same rule, and the
first-cycle alternative-explanation controls did not reproduce its complete
prediction vector. The rule nevertheless failed every prospective transfer
case. World J did not reproduce the pattern, and repeated requests elsewhere
often produced different functions.

The next problem is therefore attribution under variable cold inference:

> How can Formation determine whether receiving an external result changes
> later model-authored functions relative to prospectively matched
> alternatives, when cold calls themselves vary?

Transfer and revision remain separate prospective questions. They must use
predeclared units and cases rather than adopting the World K draw as the
practitioner's acquired object. This is a problem definition. It does not
select repeated sampling, a statistical test, a decoding change, a different
prompt, or another contact.

## Decision

Close the executable-prediction revision exploratory route as a consumed
contact with null Formation and validation verdicts. Preserve the World K
event as an atomic observation and the packet-wide variation as a validity
threat. Do not promote either into a mechanism finding.

If this problem definition survives independent review, only a separate
analytical route-selection document is licensed next. That analysis must keep
an explicit stop available. It inherits no permission for a budget, cases,
prompt, mechanism, implementation, runner, or model call.

## Evidence that created this boundary

The completed
[contact record](../evidence/executable-prediction-revision-contact-20260818/README.md)
contains 35 logical calls in 35 physical attempts with no retry. The retained
responses replay through the frozen runner and reproduce every request,
logical record, protocol proposal, and summary. Both terminal verdicts are
null.

Three groups of facts must remain separate.

### The interface stayed open

Every model call returned content. The total rule language kept all 36 authored
rule slots executable: 11 became recognized conditional rules and 25 remained
literal rules. Some literal rules looked like JSON, and some began with the
rule marker, but they did not satisfy the exact language. They were observed as
model behavior rather than treated as admission failures.

This shows that the contact could continue through imperfect interface use. It
does not show that the model understood or acquired the target function.

### World K produced one candidate event

The first World K parent predicted the primary case incorrectly. After the
environment issued the actual result, the selected successor predicted that
case correctly. Its byte-identical repeat returned the same raw rule and the
same nine-case function.

The first-cycle result-withheld, parent-withheld, same-response,
repeated-occurrence, deterministic-restatement, visible-material, and static-
instruction controls did not reproduce the selected function. This rules out
an exact-output collapse with those particular draws. It does not estimate how
often any condition would produce the function.

The selected successor's complete function predicted `qoril` on K1 and K5 and
was out of scope on the other seven cases. It was correct on K1, the primary
test, and wrong on K5, a non-transfer case. Relative to the parent, it also
turned the correct K0 acquisition prediction into out of scope and the correct
K5 non-transfer prediction into a wrong answer. It was correct on neither
transfer case, neither copy-control case, the other non-transfer case, the
acquisition case, nor the later-revision case. The observed change therefore
contains one improvement and two regressions; it is not a tidy primary-only
patch or acquired competence.

### Static model behavior stayed below the instrument ceiling

The two static model calls received the complete target zone relation. Both
outputs began with the exact marker, but neither contained one valid rule in
the frozen language. The total parser kept each complete output as a literal
rule. Both were wrong on all nine cases, and neither complete vector matched
World K's first selected successor.

Separately, the protocol-authored static ceiling expressed all nine oracle
results correctly in both worlds. Those ceiling rules never entered a model
request. They show that the rule language could represent the target relation;
they do not show that the model could author it under static instruction or
after experience.

### The packet exposed sampling and replication limits

The repeated parent request changed the function in both worlds. World J's
first-cycle repeated successor changed the selected function; that
primary-correct repeat was also produced when the external result was
withheld.

World J's later parent predicted J8 in scope and disagreed with the external
result. The later selected successor, later repeat, and later result-withheld
call all reproduced World J's first-cycle selected successor. It remained
wrong on J8.

World K's later parent was out of scope on K8, so the later result was not
counterevidence to that parent. The later selected output and its
byte-identical repeat disagreed. The later result-withheld output reproduced
World K's first-cycle selected rule, which served as the parent for that later
cycle; it did not produce a revised function.

One selected draw and one repeat per world can reveal equality or difference.
They cannot estimate a condition's output distribution. The absence of an
exact match in a control cell therefore cannot by itself show that the
external result caused the World K function.

## What remains unknown

The record is compatible with several accounts.

- The external result may have changed which function the model was likely to
  author in World K.
- The selected and repeated World K calls may have landed twice on a function
  that the cold model could produce without that result.
- Differences in visible prompt content, not the semantic status of the result
  as a consequence, may have shifted the completion.
- The first World K parent may have made one particular correction unusually
  salient, while World J's literal parent created a different task.
- The model may have local correction ability without a relation that can
  transfer.
- The interface burden may have changed which reasoning became visible, even
  though total parsing kept every output observable.

The packet cannot rank these accounts. Its mirrored worlds are different
specimens, not replications of one stochastic condition, and its controls
mostly change more than one visible prompt feature.

## The next hard problem

A next route-selection analysis must decide what observation, if any, could
count as a condition-level change rather than another convenient sample. It
must keep at least four questions distinct:

1. **Availability:** can the cold model author a recognized conditional
   function, rather than only a total-language literal?
2. **Condition effect:** does receiving an external result change the
   distribution of authored functions relative to a prospectively matched
   alternative?
3. **Transfer:** do prospectively assigned result-exposed histories improve new
   related cases relative to matched histories while staying silent on
   unrelated cases?
4. **Revision:** among prospectively assigned histories with an in-scope
   prediction, does later counterevidence change authored functions
   appropriately relative to matched histories without selecting a favorable
   parent after contact?

This contact kept all authored strings observable under the total rule
language, but it did not establish general model capability under the
conditional interface. It exposed the second question without answering it.
It did not answer the third or fourth. A future design may place these
questions in one predeclared packet only if each has its own observable
denominator and the later questions do not become conditional on selecting a
favorable earlier sample.

## Pressures on route selection

No route is chosen yet. Any later comparison must explain how it handles these
pressures.

- **Prospective unit.** Define whether the unit is an exact string, an
  executable function over frozen cases, or a scored behavioral outcome before
  seeing outputs.
- **Sampling.** Explain how the route handles the observed one-draw and
  one-repeat variability. Repeated draws, a prospectively fixed decoding
  regime, a matched-parent design, or an analytical stop remain possible
  responses; none is selected here. Do not sample until a preferred rule
  appears.
- **Matched exposure.** Separate the external result's information from call
  count, parent replay, prompt length, visible vocabulary, and generic revision
  instruction as far as the chosen claim requires.
- **No runtime answer.** The runtime may preserve, deliver, parse, and evaluate.
  It may not state the target relation, choose a favorable function, or turn
  the oracle result into an answer-shaped lesson.
- **Same-model baseline.** Compare against the same cold model under frozen
  static and persistence alternatives. A different model is a different
  experiment, not a repair.
- **Full denominator.** Retain literal, malformed-looking, overbroad,
  out-of-scope, unchanged, and unavailable outputs in their assigned cells.
- **Transfer separation.** A primary-case correction remains local until
  prospective transfer and non-transfer cases support more.
- **Cost.** Any route that proposes more draws or worlds must explain what
  uncertainty they reduce and why the added contact and token cost is
  justified before a later charter fixes a budget.

Exact repeatability may remain a useful observation. It must not serve as a
binary substitute for condition-level evidence.

## Apparent solutions that do not close the problem

The following would make the next result easier to obtain without resolving
the exposed uncertainty:

- rerunning World K and counting another matching answer as replication;
- increasing samples and reporting only the most common or most accurate rule;
- rejecting literal rules until the model produces a conditional one;
- lowering temperature after seeing instability and comparing the new packet
  directly with this one;
- replacing Qwen because another model follows the rule syntax more often;
- giving a worked correction, target relation, or oracle-authored explanation
  to every successor;
- calling exact string recurrence evidence of causal revision;
- calling one primary-case correction transfer; or
- allowing a scorer or governor to choose which successor enters later work.

These may be useful engineering interventions in another context. None alone
answers whether consequential experience changed the practitioner.

## Authority and lineage

The model owns raw parent and successor outputs. The environment owns the
external result. The runtime owns exact retention, declared delivery, and any
mechanism-authorized eligibility operation. The harness owns prospective
assignment, forks, budgets, and evidence capture. The scorer owns only frozen
post-contact measurements.

Any later call must cite the exact public parents it received. A second sample,
parent replay, result delivery, withheld result, static instruction, false or
sham content, and later counterevidence are different causal parents. A route
may compare them, but it may not collapse them under a generic label such as
`reflection` or `revision`.
