# Post-executable-prediction route selection

Status: **independently review-stable analytical selection; one separate
mechanism proposal is licensed and may stop analytically; no domain, prompt,
case packet, budget, implementation, runner, model call, validation packet, or
Formation claim is licensed**.

## Decision

Select an **unselected lineage continuation** for mechanism design.

Every prospectively assigned history continues into later cold-model behavior,
regardless of whether its intermediate model-authored output is conditional,
literal, awkward, wrong, unchanged, or unavailable. The intermediate output is
a possible mediator to preserve and ablate. It is not an admission gate and is
not the experiment's endpoint.

The selected route asks:

> Across prospectively assigned histories, does an experience with an external
> result lead to a different distribution of later cold-model actions than
> matched no-persistence, raw-persistence, result-withheld-authorship, ablation,
> and static-instruction histories, and do any beneficial differences appear on
> new related cases without appearing on unrelated cases?

This route does not adopt the World K function, reuse its cases, or assume that
the model must author a rule in the existing language. It chooses a causal
shape for later specification, not a successful mechanism.

## Why the endpoint moves to later behavior

The completed executable-prediction contact made intermediate authorship
observable. It did not make an authored rule into acquired competence.

World K's first selected successor repeated and differed from its first-cycle
controls, but its complete function contained one improvement and two
regressions. It solved no transfer case. Packet-wide repeated calls also varied.
More samples of successor text could estimate that authorship distribution,
but the research program could again become a screen for whether the model
produces a convenient intermediate object.

Formation's object is later practice. A model-authored interpretation matters
only if it can contribute to later action under governed lineage. The next
mechanism should therefore preserve intermediate outputs exactly, carry every
assigned history forward, and score later cold-model actions on cases frozen
before contact.

This does not erase the authorship result. Intermediate outputs remain evidence
for mediation and failure analysis. They simply cannot decide which histories
receive a future.

## Routes considered

### Repeat the authorship-only packet

A larger number of parent, successor, and control draws could estimate how
often each executable function appears. This would address the sampling limit
directly.

It is not selected. Function frequency is useful instrument evidence, but it
still ends before practitioner behavior. It also creates pressure to define a
preferred function class and then admit only histories that produce it. That
would extend the screening pattern the project is trying to leave behind.

### Make decoding deterministic

A prospectively fixed deterministic decoding regime could reduce visible call
variance and simplify exact comparisons.

It is not selected. Determinism can make one wrong or prompt-bound completion
repeatable. It changes the inference regime without establishing that an
external result caused a useful change. The observed model and its ordinary
variance are part of the phenomenon, not noise that must disappear before
development can be studied.

### Continue the World K successor

The exact World K rule could be retained and tested on later model actions.

It is rejected. The rule is known to contain a primary improvement and two
regressions. Selecting it after reading the packet would give a favorable draw
a developmental future that the other assigned histories did not receive.
Fresh cases would not repair that selection error.

### Give a complete static relation

The model could be asked to author a static rule, with its output then used as
the reference point for later action.

It is not selected as a research route. Static instruction remains a required
same-model baseline, but static authorship would add another intermediate and
another sampling problem. In the selected route, the static branch is instead
one explicit lesson frozen by the protocol before contact and delivered
directly to the later cold action. The first later action is retained whether
or not it follows that lesson. There is no static-authoring call to repair or
select.

### Stop after the closed exploration

The project could conclude that the current text-mediated setup cannot
separate semantic consequence use from ordinary prompt effects at acceptable
cost.

This remains the fallback if mechanism review cannot specify a fair,
nonselective later-behavior comparison. It is not selected now because the
existing runtime can preserve exact lineage, the environment can issue
independent results, and the current contact exposed a concrete mixed event
that a full-lineage comparison can test without reusing it.

## Selected causal shape

The mechanism proposal may choose a small domain, but every prospective branch
must end at the same later cold-model action and external scorer. The paths to
that common endpoint differ:

```text
no-persistence: assignment -> experience -> no retained foreground
                                      -> later cold action -> external score

raw:            assignment -> experience + external result
                         -> exact raw foreground -> later cold action -> score

authorship:     assignment -> shared parent and experience
                         -> result exposed or withheld as assigned
                         -> exact model-authored intermediate
                         -> exact intermediate foreground
                         -> later cold action -> score

ablation:       assignment -> exact same result-exposed intermediate
                         -> intermediate retained but not delivered
                         -> later cold action -> score

static:         assignment -> frozen explicit lesson foreground
                         -> later cold action -> score
```

Every branch reaches the later action unless a provider failure exhausts a
predeclared symmetric stop. Parsing, correctness, exact repetition, governor
admission, or resemblance to a target rule cannot control continuation.
If an authorship response has no content, its later foreground is empty and the
unavailable intermediate remains a harness-only fact. The runtime does not
invent an absence lesson. That assigned unit still reaches later action and
counts in every denominator.

Within each prospective block, the harness must fork the same retained parent
and occurrence before the result-exposed, result-withheld, and ablation
authorship histories differ. It may assign conditions, cases, budgets, and
later offers before contact. It may not choose which parent, successor, or
later action looks most promising.

The runtime may retain and deliver exact model strings. It may record whether a
model-authored intermediate is recognized or eligible under a later mechanism.
It may not translate an external result into a rule, repair the model output,
or execute an intermediate rule as the practitioner's later action.

The later cold model must still choose the action. A frozen evaluator may score
that action after commitment; it may not choose it.

## Required branch matrix

The later mechanism must use one model-visible later-action wrapper with one
generic foreground slot. Branch names and hidden assignments never enter that
wrapper. The exact content of the slot follows this matrix:

| Branch | Authorship call | Result visible during authorship | Later foreground |
| --- | --- | --- | --- |
| No persistence | none | no | empty |
| Raw persistence | none | no | exact occurrence plus exact external result |
| Result-withheld authorship | yes, from the shared parent and occurrence | no | exact withheld-result intermediate only |
| Result-exposed authorship | yes, from the shared parent and occurrence | yes | exact result-exposed intermediate only |
| Ablation | no separate call; fork the exact result-exposed intermediate | yes, in the shared upstream call | empty; the exact intermediate remains retained but hidden |
| Static instruction | none | no | one explicit lesson frozen before contact |

The parent, raw occurrence, and external result are not re-delivered to later
action in either authorship branch. Recognition kind, parser output,
eligibility, correctness, branch name, and quality labels are harness-only and
never enter later action. The raw branch contains no model-authored
intermediate. The static branch contains no developmental occurrence or model-
authored intermediate.

Within a block, result-exposed delivery and ablation fork only after one exact
result-exposed intermediate has been retained. They do not make two independent
authorship calls. The delivery contrast therefore changes only whether that
same string occupies the later foreground slot.

These roles support specific contrasts and no stronger ones:

- raw persistence versus no persistence measures the effect of delivering the
  exact occurrence and result together;
- static instruction versus no persistence measures the effect of the frozen
  lesson;
- result-withheld authorship versus no persistence measures the effect of
  delivering an intermediate authored without the result;
- result-exposed authorship versus result-withheld authorship measures the
  complete pathway associated with exposing the result during authorship,
  including the different model-authored strings it may produce;
- result-exposed authorship versus ablation measures the effect of delivering
  the exact result-exposed intermediate after the same upstream history and
  authorship responsibility; and
- ablation versus no persistence is a cold-request audit because both later
  requests have empty foreground. It cannot establish a developmental effect.

Result-exposed authorship versus raw persistence and versus static instruction
are comparative same-model performance baselines. They change both lineage and
visible foreground content and therefore do not isolate authorship as a single
cause.

A same-response branch is required only if the later claim distinguishes
runtime retention from generating and using an intermediate within one model
call. If a fair same-response request cannot fit the common interface and
budget, retention-specific language remains unavailable; the contact need not
be blocked if its weaker question does not require that claim.

## Prospective behavioral cases

Later cases must be assigned before participant output and divided into at
least:

- acquisition cases that expose immediate use of the experienced result;
- transfer cases that require the same underlying relation with new surface
  tokens or situations;
- non-transfer cases where that relation should not control action; and
- copy controls where episode answer tokens cannot solve the case.

Every branch receives the same case roles and action interface. Cases used in
the completed contact are consumed and cannot become prospective evidence.

The mechanism must define a direct environment oracle for later actions. An
interpreter of intermediate text may supply diagnostic features, but those
features cannot replace action outcomes or determine continuation.

Revision is not part of the selected first comparison. It requires an in-scope
claim and later counterevidence without selecting a favorable parent. A later
revision route can be considered only after a prospective full-lineage packet
produces a condition-level acquisition or transfer observation worth revising.
This ordering is analytical, not a positive gate: a null or messy first packet
completes the route rather than triggering model search.

## Handling cold-call variation

The selected route treats variation as part of the outcome. A later mechanism
must use prospectively formed blocks so that each history condition receives
the same model, interface, case roles, and sampling policy. It must retain every
assigned unit.

This document does not choose the number of blocks, draws per block, decoding
settings, statistic, or decision threshold. The mechanism must explain how its
design can distinguish a condition pattern from the degree of variation seen
in the completed packet. That explanation may use replication, paired forks,
a fixed decoding regime, descriptive uncertainty with weak claims, or an
analytical stop. It may not select the best output from repeated draws.

No single intermediate string becomes the unit of success. The minimum
condition-level report must include all assigned later actions, unavailable
actions, and branch denominators. Exact intermediate equality, executable
function equality, and later action equality remain separate measurements.

The result-exposed and result-withheld intermediate distributions are mandatory
secondary evidence. At minimum, the record retains content availability, exact
bytes, and any domain-independent recognized form fixed before contact. A later
mechanism may add a frozen domain scorer. These diagnostics can show where two
pathways diverged; they cannot determine continuation or replace the later-
action contrast.

## Matched exposure and residual prompt differences

The result-exposed and result-withheld authorship requests must use the same
model, system message, responsibility, parent, occurrence, field order,
sampling policy, token ceiling, call count, and stopping rule. They differ only
in the prospectively declared result field. The exact representation of
withholding must be frozen before contact.

All later-action requests must use the same model, system message, action
responsibility, case presentation, foreground field, field order, sampling
policy, token ceiling, call count, and stopping rule. They differ only in the
foreground bytes fixed by the branch matrix.

Different foreground contents naturally produce different prompt bytes and
token counts. The evidence must report those deltas for every branch and keep
ordinary prompt-content effects live. Matching wrapper structure or branch
labels does not make two prompts semantically isolated. A mechanism may use a
prospectively constructed mass control only for a claim that requires it; lack
of such a control limits the claim rather than silently blocking all contact.

## What the selected route can and cannot show

A well-specified packet could show that result-exposed histories have a
different later-action distribution from named predeclared histories on fresh
cases. Each pair supports only the contrast named in the branch matrix. If a
supported difference is beneficial on transfer cases and quiet on non-transfer
cases, it could support a bounded acquisition, transfer, or selectivity
observation.

It would not by itself show durable development, revision, net value, or a full
Formation effect. It also could not make the cold model experience semantic
provenance apart from the text and structure used to represent that provenance.
Static, raw, withheld, and ablation branches limit simpler accounts; they do
not remove all prompt-content explanations.

If only the static branch improves, the result is static instruction
competence. If raw and result-exposed histories perform equally, that equality
alone does not identify why; their later foregrounds and upstream lineages
differ. If result-exposed and result-withheld histories move together, this
packet shows no later-action difference for the complete authorship-time
result-exposure pathway. If result-exposed delivery and its ablation move
together, influence from delivering that intermediate is unsupported. If all
branches vary without a condition pattern, the result is a completed null
under the frozen budget.

## Loses-conditions before a charter

The route loses before contact if a mechanism:

- makes later action conditional on parsing, correctness, eligibility,
  repetition, or reviewer approval of an intermediate;
- selects a parent or intermediate after observing hidden truth or later
  performance;
- reuses the World K rule, cases, answers, or control outcomes as prospective
  evidence;
- gives the model a worked relation, action answer, or oracle-authored lesson
  in a branch described as model-authored development;
- lets the runtime or evaluator execute the intermediate relation for the
  practitioner;
- changes model, action interface, case roles, sampling policy, or stopping
  rule across the compared branches;
- changes system message, later-action wrapper, foreground field, case
  presentation, later-action call count, or token ceiling across branches
  beyond the exact foreground bytes declared in the matrix;
- lets result-exposed and result-withheld authorship differ in parent,
  occurrence, responsibility, field order, sampling policy, call count,
  stopping rule, or any visible field other than the frozen result
  representation;
- omits exact prompt-byte and token-count deltas or treats a shared wrapper as
  proof that prompt-content effects are absent;
- leaves ambiguous whether the result is visible during authorship or whether
  the occurrence, result, parent, intermediate, or lesson reaches later action;
- omits raw, withheld, static, no-persistence, or ablation histories while
  making the causal claim that branch would test;
- reports only recognized rules, correct actions, or completed outputs;
- reports acquisition, transfer, or selectivity from a subset of branches,
  case roles, or assigned later actions rather than full predeclared branch by
  role denominators;
- treats more samples, deterministic decoding, or interface repair as
  developmental progress;
- makes a second contact conditional on a null or awkward result; or
- lacks an analytical stop before implementation.

## Next boundary

If independent review finds this selection sound, one separate mechanism
proposal may define the domain, authorities, branch information, lineage,
later-action interface, prospective case roles, outcome measures, and
loses-conditions. That proposal may conclude that no fair packet is currently
available.

Review stability would not license a prompt, exact cases, budget,
implementation, runner, participant-model call, validation packet, or
Formation claim.

## Review record

Composer 2.5 and Grok 4.6 independently returned `REVISE_SELECTION` on the
first draft. Both accepted the move to unselected later behavior but found that
the named branches did not yet freeze what the later cold call could see. Raw
persistence and ablation could collapse, result exposure could change both
authorship-time and practice-time information, static instruction had two
incompatible meanings, and the single linear diagram did not represent the
non-authorship paths. Composer also required matched-exposure obligations and
full branch-by-case-role reporting.

The repair replaces the branch names with a complete information matrix. It
forks result-exposed delivery and ablation after one exact intermediate,
delivers only the intermediate in both authorship branches, defines static as a
pre-frozen lesson delivered directly to later action, and names the exact
contrast each pair supports. It also freezes matched request surfaces, reports
residual prompt deltas, retains intermediate distributions as secondary
evidence, and requires full denominators.

Final read-only verdicts on that repaired text:

- `composer-2.5`: `SELECTION_STABLE`
- `cursor-grok-4.6-high-fast`: `SELECTION_STABLE`

These verdicts license only the separate mechanism proposal. Neither review
contacted the participant model.
