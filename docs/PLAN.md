## Completed diagnostic: can later calls use a correct lesson?

The completed interface diagnostic supplied a known-correct lesson across four
fresh controller families, new action strings, and targets above and below.

This experiment cannot show development. The harness supplies the lesson, so a
successful result means only that the representation and delivery interface
are usable. That fact is needed before a later authorship failure can be
interpreted.

The sentence and effect table each passed every matching call. The policy did
not. Ungated sentence and table delivery harmed unrelated cases, so both forms
still require the exact-family gate. The
[evidence](../evidence/representation-consumption-calibration-20260820T112303Z/README.md)
is a delivery-interface result, not a learning result.

## Completed instrument: can experience produce that lesson?

The completed experiments removed the supplied answer. The model acted,
received an environment-issued consequence, and authored the retained
representation itself.

Those comparisons included an author who saw the consequence and one who saw
the same action without it. The harness defined the empty representation form
but did not fill the controller relation or later action policy.

The contacts compared relation sentences and effect tables across fresh
experiences, both selected slots, and repeated identical requests so ordinary
output variation remained visible.

Direct sentence and table authorship were not reliable. Staging a direct
model-written observation before table authorship repaired that failure across
eight fresh experiences. A two-world action successor reproduced the complete
chain but stopped null on its frozen per-cell raw comparison.

## Completed milestone: counterevidence accumulation

This milestone froze a small deterministic contested-consequence specimen
before model contact. It began with one admitted claim and appended several
exact occurrences without editing or summarizing them away.

The specimen included at least three histories:

- repeated complete movements that consistently contradict the current claim;
- one contradictory movement followed by support for the current claim; and
- incomplete or explicitly contested movements that cannot settle the claim.

It defined runtime-visible policies for supersession, suspension, and no
change. The policy could count exact eligible occurrences, but retained their
individual sources and order. It did not use a harness truth label, treat
missing evidence as a vote, or turn the scorer verdict into governance.

The deterministic result and bounded learned continuation are complete. The
learned run kept the histories small, retained every clerk proposal and source,
and compared each final state with cold, raw history, supplied records, newest-
proposal use, and causal removal. Its formal null routed to the completed fresh
recovery-influence successor described above.

## What happens after a mechanism survives

Exploration is allowed to find variance, malformed output, harmful behavior,
or a null result. Once repeated evidence identifies a mechanism worth claiming,
move it into stricter validation.

Validation freezes the full comparison before contact. It requires repeated
same-model baselines, prospective transfer and non-transfer cases, external
consequences, causal removals, and a scorer that cannot be changed after seeing
the result.

Only after a mechanism survives validation should the project study longer
developmental trajectories. Those later experiments can ask whether several
lessons compose, interfere, decay, recover after error, or respond to
counterevidence. Exceptional real-world practice belongs later still and must
be compared with the same cold model using strong static instructions and
ordinary persistence.

## Supporting implementation lane

The deterministic runtime and trajectory harness continue only when they
supply an instrument needed by the active experiment. The runtime preserves
developmental lineage and governs later influence. The harness creates
controlled histories, forks comparisons, schedules environments, and records
evidence. The harness may measure development; it may not secretly perform it.

The implementation preserves exact source identity, branch conditions, replay
constraints, foreground delivery, encounter opening, practice requests, model
proposals, committed actions, environment results, and closed experience
intervals. Extend it only when the empirical question needs more general
machinery.

## Working rules

1. State one concrete question and the observation that would matter.
2. Build only the instrument needed to answer it.
3. Record the model, interface, budget, stopping rule, and evidence destination
   before contact.
4. Retain malformed, unavailable, and harmful outcomes instead of screening
   them away.
5. Replay computed evidence from raw requests and responses.
6. Report the result in plain language before its audit details.
7. Let the result choose the next question.

An operational failure before any participant-model request is an engineering
failure, not a scientific contact. Repair it directly. Do not create a new
research route merely to retry the intended experiment.

Cursor reviews are optional internal criticism and require human approval.
They are not external peer review, experimental evidence, or routine gates.
