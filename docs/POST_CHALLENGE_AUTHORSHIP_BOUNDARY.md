# Post-challenge authorship boundary

Status: **independently review-stable post-contact problem definition; a
separate route-selection analysis is licensed, but no mechanism, prompt repair,
model change, rerun, successor contact, validation packet, or Formation claim
is licensed**.

## Decision

Close the exact-draft challenge route as a completed null exploration and name
the narrower problem it exposed.

The contact did not produce a stable, control-qualified revision. That is not a
reason to repair the prompt and try again. It is evidence about the difficulty
of getting a cold model to author a reusable proposition from consequential
experience without the runtime writing, selecting, or enforcing that
proposition.

## Contact facts

The [exact-draft contact](../evidence/draft-challenge-exploratory-contact-20260818/README.md)
completed all 39 calls with no retry. Both direct conditions were stable, and
the byte-identical withheld calls reproduced them. The source draft was
therefore fixed without favorable sample selection.

What happened after delivery differed by world:

- In World G, two identical exact-draft challenge requests returned different
  candidates. There was no stable challenge anchor.
- In World H, both exact-draft challenge requests returned the source candidate
  exactly. Exact replay and repeated occurrence returned it too.
- World H’s prompt-mass control stably copied its deterministic uppercase
  control string into `change`.
- Thirty-four candidate replies parsed. The frozen governor admitted none; 32
  copied an acquisition action token in `change`.

Both prompt-mass controls matched the exact challenge’s prompt-token count
locally and at the provider. Token measurement is therefore no longer the
reason the complete comparison failed. World G lacked a stable challenge
anchor and also had unavailable or unstable control cells. World H’s stable
challenge exactly matched its source, while three other conditions were
unstable. Those are the reasons neither complete label could issue.

Action-token copying and World H’s mass-control-string copy are separate
descriptive observations. They help define the open authorship problem, but the
charter does not use them as additional complete-label gates.

The contact’s strongest permitted report is still per-condition observation.
Both mechanism labels, the Formation verdict, and the validation verdict are
null.

## What remains unknown

Several explanations remain compatible with the record.

The model may treat `draft_content` as text to continue or copy rather than as a
claim to examine. The stable uppercase mass copy in World H makes this a live
explanation.

The candidate responsibility may be too open-ended to select one proposition.
World G’s challenge replies kept the same action token but invented different
counterevidence. That is compatible with ordinary sampling among plausible
completions.

The two-field candidate interface may reward short token-shaped answers. A
schema that forbids such answers could repair output shape without creating the
missing reasoning, just as the earlier structured-output trial repaired JSON
without repairing computation.

The occurrence may contain enough public facts for a capable model to state a
relation, yet this model and responsibility may not do so reliably. Conversely,
longer relational prose in some samples does not prove that a reusable
abstraction was formed. No semantic scorer was frozen for this contact.

The evidence cannot rank these explanations. It also cannot tell whether a
different model, prompt, sample count, or representation would help.

## The next hard problem

The project now needs to ask:

> How can a model-authored process turn consequential experience into a stable,
> scope-bounded, falsifiable proposition without copying an arbitrary visible
> string, while the runtime neither states the proposition nor selects a
> favorable sample?

Each phrase carries a necessary pressure:

- **Model-authored:** the runtime and harness cannot write the relation.
- **Consequential:** the source must preserve action and external result, not a
  static lesson alone.
- **Stable:** repeated identical requests must reproduce the candidate before a
  named change can be compared.
- **Scope-bounded:** the candidate must say where it applies.
- **Falsifiable:** it must say what later observation would count against it.
- **Not arbitrary copying:** success cannot be earned by echoing an action
  token, source draft, restatement, or length-matched control string.
- **No favorable selection:** malformed, awkward, null, or unhelpful first
  outputs remain part of the phenomenon.

These pressures describe the problem. They do not yet choose a mechanism or an
output schema.

## What would not solve it

The following changes may improve an interface while leaving the research
problem untouched:

- banning hexadecimal strings or requiring sentence-length fields;
- increasing sample count until one answer looks useful;
- choosing a more articulate source draft after seeing outputs;
- giving the governor’s refusal back to the model as answer-shaped feedback;
- writing the phase relation into a schema, rubric, lesson, or example;
- using a stronger model and treating fluency as evidence of formation; or
- scoring a later changed answer without raw, static, same-model, transfer, and
  non-transfer comparisons.

Any future proposal must explain what causal uncertainty it resolves beyond
these repairs.

## Work licensed by this draft

This draft licenses only read-only analysis and adversarial review of the
retained contact and this problem statement. Review should try to show that the
problem is already answered by a simpler prompt-content, sampling, interface,
or capability account.

If the problem survives review, a separate route-selection document may compare
possible authorship processes. That later document must keep analytical stops
available. It may not inherit permission for a model call from this contact.

The consumed charter licenses no rerun or successor. No new participant-model
request may occur until a new mechanism and contact earn their own authority.

## Review record

Composer 2.5 and Grok 4.6 independently checked this problem definition and the
public evidence account against the charter, terminal summary, integrity
report, and retained logical records. Composer found the first account sound.
Grok required two repairs:

1. Copying observations had been grouped with the actual reasons the complete
   labels were null, even though copying is not an additional label gate.
2. The repeated-occurrence source match had been treated as draft copying, but
   that request contained no draft and kept default authorship from occurrence
   fields as a live explanation.

The repaired documents separate formal label failures from descriptive
copying and preserve both simpler accounts. Composer 2.5 and Grok 4.6 then
returned `POST_CONTACT_ACCOUNT_SOUND` on the same final text. Neither review
contacted the participant model.
