# Availability-to-influence problem

Status: **post-contact problem definition; representation iteration closed; no
new model contact or validation protocol licensed**.

## Main point

A correct candidate can be authored, admitted, and delivered without being
used as a complete decision rule.

The explicit-consequence contact produced one exact example. In World D, the
model authored `second` as the increasing slot. The runtime derived the same
fact from environment-issued fields and admitted it. The governed request
contained that exact candidate on both same-family movement cases.

The later actor used it when the target required increasing position. It did
not use the implied inverse when the target required decreasing position.

This separates four events that must not share one name:

```text
eligibility decision
  -> delivery authorization
  -> candidate present at inference
  -> attributable influence on action
```

A receipt for any earlier event cannot establish a later one.

## Evidence that created the problem

The completed
[explicit-consequence record](../evidence/explicit-consequence-contact-20260817/README.md)
contains two mirrored cold worlds and two repetitions per cell.

In the counter-prior World D increase case:

- no persistence chose the wrong first control twice;
- raw occurrence chose the wrong first control twice;
- authored interpretation chose the correct second control twice; and
- governed delivery chose the correct second control twice.

In the World D decrease case, all four conditions chose the wrong second
control twice. The authored and governed requests carried the same correct
`increasing_slot: second` candidate in both directions.

The candidate therefore produced a later difference that raw occurrence did
not reproduce, but only for the direction named positively in its field. The
record is compatible with treating `second` as a salient direct action cue
rather than executing the full two-slot relation.

This is an exploratory manifestation, not transfer. The contacted cases are
consumed, repetitions are few, and all offers are prompt content.

## Vocabulary correction

Formation's [concept](CONCEPT.md) defines activation as attributable use of an
admitted change at a later decision boundary. The exploratory runner's
`activated` field was written before inference and means only that its public
scope gate authorized delivery.

Retain that historical field unchanged in evidence, but read it as:

```text
delivery_authorized
```

It does not prove activation. In particular, World D decrease has
`activated: true` and no observed action use. Future records must name
pre-inference authorization, actual delivery, and post-inference causal
attribution separately.

The existing deterministic `positive activation decision` contract remains a
wire-level name for a runtime decision. Its passing tests do not establish the
conceptual event of attributable influence.

## The mechanism choice now exposed

The next mechanism must say what kind of change a candidate is.

### Declarative fact plus generic applicator — reviewed and closed for validation

The candidate stores a world fact such as `increasing_slot: second`. A generic
runtime or practice procedure converts that fact and current state into an
action:

```text
target above position -> choose increasing slot
target below position -> choose other slot
target equals position -> hold
```

This can be a legitimate formed practitioner because the practitioner includes
the runtime. But the competence belongs partly to a static applicator. Any
claim must include a strong raw-occurrence path to the same applicator and
price the runtime computation. It must not be described as the cold model
acquiring the procedure.

This direction was selected and specified. The
[calibration-fact applicator specification](CALIBRATION_APPLICATOR_MECHANISM.md)
defines the limited situated-knowledge question, a transient raw derivation
comparator, and an exact influence-edge ablation.

Two independent Cursor reviews then returned `REVISE_BEFORE_BUILD`. Their
[review record](CALIBRATION_APPLICATOR_VALIDATION_REVIEW.md) showed that once a
correct fact reaches the deterministic applicator, both later directions work
by construction. The design can test caching and runtime governance, but its
positive action contrast cannot establish acquired model-mediated competence.
It is closed as the next claim-bearing mechanism.

### Model-mediated procedural influence — current problem

The interpreter authors both the acquired fact and how it should control later
decisions. The governor checks only what the observed consequence and public
practice invariant warrant. The later actor receives the exact admitted
procedure.

This keeps authorship with the model but raises a new question: whether the
candidate schema or interpreter prompt already supplies the conditional
procedure. A form with answer-shaped branches can move the missing competence
into protocol text as easily as a runtime applicator can.

This is now the [current analytical problem](PROCEDURAL_INFLUENCE_PROBLEM.md).
It needs a new account of how candidate form avoids supplying the missing
procedure in the schema while leaving later action with the cold model.

## Requirements before validation

A mechanism specification must now freeze:

1. whether the acquired object is a fact, a procedure, or both;
2. which generic practice competence is shared statically across every branch;
3. what the model must author from consequence rather than copy from a schema;
4. what the governor may check from runtime-visible evidence;
5. what pre-inference event authorizes delivery;
6. what evidence can establish actual influence after the action;
7. a public ablation that removes one named causal edge without changing
   foreground or unrelated state; and
8. natural-cost comparison with raw occurrence and the same static applicator.

Fresh prospective cases must require both directions, change all action tokens,
include other-family and current-state-sufficient cases, and include a
counterevidence path. The cases contacted in either calibration exploration are
not eligible.

## Losing observations

The next design loses or changes interpretation if:

- delivery receipts are counted as activation without a behavioral causal
  test;
- a static applicator contains the realized hidden calibration;
- a candidate form supplies the full case-conditioned answer rather than a
  representation the model authored;
- the governor derives or repairs candidate content from hidden profiles or
  prospective answers;
- a procedural candidate helps only the positively named direction;
- other-family guesses or current-state work increase with availability;
- governed behavior does not differ from always-authored behavior on any
  predeclared governance pressure;
- raw occurrence plus the same generic applicator matches the candidate
  mechanism after costs; or
- an ablation changes request foreground or branch state beyond its named edge.

Raw persistence is allowed to win. A correct candidate with no complete later
influence is also a legitimate null mechanism result.

## Current boundary

Do not run another model, formatter, prompt repair, or calibration case packet.
The next work is representation and domain analysis for model-mediated
procedural influence. Only a mechanism whose later competence is not executed
by the runtime or supplied by its candidate form may freeze fresh validation
cases.
